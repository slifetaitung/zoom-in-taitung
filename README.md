# Zoom in Taitung 線上翻頁書

把《Zoom in Taitung》的印刷版 PDF 轉成網頁翻頁書，嵌進 Google Sites。

**這份文件寫給非工程背景的接手同事。** 照著章節順序做即可，
不需要看懂 `tools/` 裡的程式。

## 一、需要準備的東西

| 項目 | 說明 |
|---|---|
| **Python** | 已安裝（處理 PDF 用）。確認方式：命令列輸入 `python --version` |
| **單位的 GitHub 帳號** | 放網站用。**不要用個人帳號**，人走了帳號就帶走了 |
| **Google Sites 的編輯權** | 那個站在公司另一個帳號底下，需要對方把你加為編輯者 |
| **螢幕版 PDF** | 見下方「PDF 要什麼樣的」 |

### PDF 要什麼樣的

跟設計端要檔案時，講清楚這四點，可以省掉很多來回：

1. **單頁（Pages），不要跨頁（Spreads）** — 拿到跨頁檔程式會自動切半，但切點壓到跨頁大圖時品質較差
2. **螢幕版，不要印刷版** — 印刷版帶 3mm 出血，程式會自動裁掉，但轉圖前先給對的檔比較保險
3. **RGB，不要 CMYK** — CMYK 轉出來顏色會偏
4. **書封另外一個檔** — 封底、書背、封面攤平在同一頁的那種

## 二、新增一期（三個指令）

假設新的一期是 vol.3，把兩個 PDF 放進 `電子書` 資料夾，
然後**在「電子書」資料夾底下**打開命令列，依序執行：

```
python tools/split_render.py pages "生活誌vol3_內頁.pdf" docs/pages/vol3
python tools/split_render.py cover "生活誌書封_vol3.pdf"  docs/pages/vol3
python tools/make_manifest.py docs/pages/vol3 "Zoom in Taitung vol.3" 2026
```

第三個指令會告訴你總頁數。**最後把 `docs/js/book.js` 第 5 行改成新的一期：**

```js
const ISSUE = 'vol3';
```

改完就完成了，其他檔案都不用動。

### 如果第三步報錯「總頁數是奇數」

翻頁書需要偶數頁，封底才能單獨一頁。
請設計端在內頁最後補一張空白頁，重跑一次即可。

## 三、發布到網路上（GitHub Pages）

1. 用**單位的 GitHub 帳號**登入，建一個新的 repository，例如 `zoom-in-taitung`，設為 **Public**
   （Pages 免費方案只能從 public repo 發布；就算設 private，發布出來的網站內容一樣是公開的）
2. 把**整個專案**上傳到 repository（含 `tools/`、`README.md`、`docs/`）
3. 進 repository 的 **Settings → Pages**
4. Source 選 **Deploy from a branch**，分支選 `main`、**資料夾選 `/docs`**，按 Save
5. 等 1–2 分鐘，頁面上方會出現網址，長這樣：

   `https://slifetaitung.github.io/zoom-in-taitung/`

6. 用瀏覽器打開這個網址，確認翻頁書會動

> 圖片檔加起來約 120 MB，在 GitHub 的免費額度內，不用擔心。

## 四、嵌進 Google Sites

Google Sites 在公司另一個帳號底下，需要編輯權才能操作。

1. 打開要放的頁面，右側面板選 **嵌入 → 嵌入程式碼**
2. 貼上這段，把網址換成上一步拿到的：

```html
<iframe src="https://slifetaitung.github.io/zoom-in-taitung/"
        style="width:100%; height:760px; border:0;"
        allow="fullscreen"
        title="Zoom in Taitung 線上翻頁書"></iframe>
```

3. 按下一步 → 插入，然後在頁面上把方塊**拉到最寬**
4. **發布**

### 高度為什麼是 760px

Google Sites 的嵌入高度是寫死的，不會跟著內容伸縮。**760 不是隨便取的**。

翻頁書在「兩頁並排後的總寬度滿 1000px」時才顯示跨頁。而書本尺寸是由
**高度**回推的（要讓整本塞得進 iframe，不被裁掉），所以高度不夠，
欄寬再大也湊不到 1000。實測：

| iframe 設定 | 桌機 |
|---|---|
| 高 700，欄寬 950 | 單頁（高度卡住，總寬只到 924） |
| 高 700，欄寬 1024 | **還是單頁**（高度卡住，總寬仍 924） |
| **高 760，欄寬 ≥896** | **跨頁** ✅ |

高度不夠時，**欄寬再大也沒用** —— 書本尺寸是由高度回推的
（要讓整本塞進 iframe 不被裁掉），高度撐不起來就湊不到跨頁門檻。

所以 iframe 高度請維持 **760px**。欄寬只要有 896px 以上就會跨頁，
Google Sites 的標準欄寬通常夠用，**不一定需要改成全寬版面**；
發布後看是單頁還是跨頁，是單頁再改全寬。

### 哪些裝置會看到跨頁

門檻是「兩頁並排總寬滿 880px」。實測（iframe 高 760）：

| 裝置 | 模式 | 每頁寬 |
|---|---|---|
| 桌機、iPad 橫向 | 跨頁 | ~500px |
| iPhone 15 Pro Max 以上 橫向 | **跨頁** | 458–470px |
| iPhone 14 / SE 橫向 | 單頁 | 506px |
| 所有 iPhone 直向 | 單頁 | ~414px |

> 手機橫向的跨頁是 2026-08-28 才開放的（原本規格是一律單頁）。
> 詳細數據與取捨見 `CLAUDE.md`。

### 如果手機上覺得 760px 太高

手機直向不受影響（本來就是單頁，書會自動縮小塞滿），只是上下留白多一點。
真的想改矮，代價是桌機退回單頁 —— 兩者無法兼顧，Google Sites 沒辦法
分別設定桌機和手機的高度。

## 五、發布後一定要用真機測這五項

**不要只看電腦上的瀏覽器縮小視窗**，觸控衝突和 iPhone 底部系統列
在模擬器上不會重現。請拿真的手機打開**發布後的 Google Sites 網址**：

- [ ] 1. iPhone 直向是單頁
- [ ] 2. iPhone **橫向仍然是單頁**（不可以變成兩頁並排）
- [ ] 3. 雙擊書頁能放大
- [ ] 4. 手指在書上**上下滑動**時，外層 Google Sites 仍然捲得動
- [ ] 5. 底部那排按鈕沒有被 iPhone 的系統列蓋住

## 六、不要亂動的地方

### `docs/js/book.js` 的 `MIN_PAGE_W = 440`

這個數字決定「什麼時候切成單頁」。判斷式是
`容器寬度 < MIN_PAGE_W × 2 就單頁`，所以 440 代表門檻是 880px。

**不要低於 440。** 再往下調，iPhone SE 那種小螢幕手機橫向也會變跨頁，
每頁只剩 325px，內文會小到讀不了。

（本來是 500，2026-08-28 為了讓大螢幕手機橫向能看跨頁而調降。
實測代價很小：單頁模式本來也只有 506px，跨頁後 458px，只縮 9%。）

### `docs/css/book.css` 裡的 `min-width:0 !important`

**這行不能刪。** 翻頁書的函式庫會把尺寸下限當成 inline style 貼到書本元素上，
導致容器再小、書也不會縮，超出的部分被裁掉 —— 因為書是置中的，
症狀是「**左半邊整個消失**」，手機上左右各被切掉約 55px。
那行 CSS 就是用來蓋掉它的。

### `docs/vendor/` 裡的檔案

這是翻頁書的函式庫（StPageFlip，MIT 授權），已經下載進專案自行託管。

**不要改成 CDN 連結。** 這個函式庫實際上已經停止維護
（最新版 2.0.7，約五年前），放在自己的 repo 裡才不會哪天突然消失。
壞掉沒有官方支援，只能自己修 —— 但程式碼不大，可行。

### 圖片檔名的補零（`p001` 而不是 `p1`）

補零是刻意的。不補零的話電腦排序會把 `p10` 排在 `p2` 前面，整本書頁序就亂了。

## 七、目前刻意不做的功能

全文搜尋、縮圖目錄、閱讀統計、密碼保護、右翻（RTL）模式。

**整本 PDF 下載**也已移除（原本有，2026-08-28 拿掉）。理由是版權：
翻頁書一頁一頁看，跟按一個鍵就把整本刊物存下來，是兩件不同的事。
真要加回來，`tools/make_manifest.py` 的舊版本有現成的合成程式碼（見 git 歷史）。

這些單獨看都不難，但加起來等於把商業翻頁書服務重寫一遍。
**除非真的有人反映需要，否則不要加。**
